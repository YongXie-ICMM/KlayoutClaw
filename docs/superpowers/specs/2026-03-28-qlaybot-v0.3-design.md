# qlaybot v0.3 Design Spec

**Date:** 2026-03-28
**Status:** Draft
**Scope:** 2 systems — TUI overhaul, context management with compaction
**Approach:** Build from Ink primitives up, following the same architectural evolution qdevbot took. Reference `~/qdevbot` for design patterns and Ink usage, but implement for qlaybot's KLayout domain independently — no file copying, no shared code assumptions.

## 2. Markdown Rendering

### Concept

Render assistant text as styled markdown with syntax-highlighted code blocks, replacing raw text display.

### Pipeline

1. Parse markdown via `Markdown` class from `@mariozechner/pi-tui` (add as explicit dep — currently transitive via pi-coding-agent)
2. Syntax highlight code blocks via `cli-highlight` with language alias resolution
3. Post-process output:
   - Strip `###` markers from h3+ headings (pi-tui keeps them)
   - Replace `-` bullets with `•`
   - Strip trailing whitespace per line
   - Remove blank line after headings
   - Collapse 3+ consecutive newlines to 2

### Components

- `renderMarkdown(raw, width?)` — core function in `src/tui/markdown.ts`
- `MarkdownText` component — accepts `children: string` and `indent?: number` for width calculation, prevents Ink re-wrapping

### Dependencies

- `cli-highlight` ^2.1.11 — syntax highlighting
- `marked` ^15.0.0 — markdown parsing (used by pi-tui internally)

### Files

- `src/tui/markdown.ts`
- `src/tui/components/MarkdownText.tsx`

## 3. Input System

### Concept

Replace the basic append/backspace InputBox with a full text editor featuring cursor movement, command history, and tab completion.

### useInputBuffer Hook

Reducer-based text buffer with cursor position tracking:

```ts
type InputAction =
  | { type: "INSERT"; char: string }
  | { type: "DELETE_BACK" }
  | { type: "DELETE_FORWARD" }
  | { type: "MOVE_LEFT" }
  | { type: "MOVE_RIGHT" }
  | { type: "MOVE_HOME" }
  | { type: "MOVE_END" }
  | { type: "CLEAR" }
  | { type: "SET_VALUE"; value: string };

// Returns: { value, cursorOffset, insert, deleteBack, deleteForward,
//            moveCursorLeft, moveCursorRight, moveHome, moveEnd, clear, setValue }
```

### useCommandHistory Hook

```ts
interface CommandHistoryAPI {
  push(command: string): void;        // Add to history (dedup consecutive)
  navigateUp(draft: string): string;  // Go to previous, save draft on first up
  navigateDown(): string;             // Go to next, restore draft at end
  reset(): void;                      // Clear navigation state
}
```

Persists to `~/.qlaybot/history.json` (max 500 entries).

### Tab Completion

Tab cycles through matching `/` commands. 2+ matches show a `CompletionList` dropdown. Single match auto-completes. Command list sourced from `SLASH_COMMANDS` array.

### InputBox Features

| Key | Action |
|-----|--------|
| ←/→ | Move cursor |
| Ctrl+A | Home |
| Ctrl+E | End |
| Ctrl+D | Delete forward |
| Backspace | Delete backward |
| ↑/↓ | History navigation |
| Tab | Cycle command completion |
| Enter | Submit (or select from dropdown) |
| Escape | Dismiss dropdown |

Cursor rendered with `chalk.inverse` at cursor position.

## 4. Message Components

### Concept

Decompose the monolithic MessageList into specialized sub-components matching qdevbot's pattern.

### UserMessage

Cyan `> ` prefix with 2-char gutter column + message text.

### SystemMessage

Markdown-rendered command output. Two rendering modes:
- **Plain**: Full markdown rendering via MarkdownText (for simple text output)
- **Structured**: Interactive sections with `ContextSection[]` — each section has title, summary, and expandable details (toggled by Ctrl+T). Used by `/context` and `/help`.

```ts
interface ContextSection {
  title: string;
  summary: string;
  details?: string;
}
```

### AssistantMessage

Segment-based chronological rendering:

```ts
type AssistantSegment =
  | { type: "thinking"; chunks: string[] }
  | { type: "text"; chunks: string[] }
  | { type: "tool"; tool: ToolExecution };
```

Each segment renders in order via:
- `ThinkingIndicator` — dim italic, spinner while active, truncates to last ~10 lines
- `MarkdownText` — rendered markdown for text segments
- `ToolPanel` — compact/expanded tool execution display

Footer shows elapsed time after completion.

### ThinkingIndicator

| State | Display |
|-------|---------|
| Active streaming | Spinner + last ~10 lines + `[N lines hidden]` |
| Completed, expanded | Full thinking text, dim italic |
| Completed, collapsed | Hidden |

### ToolPanel

**Compact mode (default):**
- Header: tool name + key argument + duration
- Summary: line count, diff preview, or status
- Smart argument extraction per tool type:
  - `bash` → command string
  - `read` → file path
  - `edit` → file + line count
  - `write` → file + line count
  - KLayout tools → tool-specific arg

**Expanded mode (Ctrl+T):**
- Full arguments JSON
- Full result output (truncated to 8 head + 8 tail if >16 lines)

## 9. BackgroundBar Upgrade

Interactive panel replacing the current simple counter.

**Collapsed:** Summary hint (`2 running, 1 done`).

**Expanded (Ctrl+G):** Bordered task list with:
- Live elapsed timers (updates every second)
- `k` = cancel selected running task (requires `cancel(id)` method on BackgroundTaskManager)
- Up/Down to navigate
- Escape to close

Hidden when no background tasks exist.

### BackgroundTaskManager Extensions

Add `cancel(id)` method to `src/background/index.ts` — sets task status to `"cancelled"`, calls optional AbortController. Add `subscribe()` for task state change events (already exists in v0.2).

### Note: Ctrl+B "Move to Background" — Deferred

Moving a running tool to background (qdevbot's `BackgroundSignal` + wrapper pattern) requires a signal/wrapper layer that intercepts tool execution mid-flight. This is architecturally non-trivial and deferred to a future version. The BackgroundTaskManager's existing `run()` API handles pre-declared background tools.

### File

`src/tui/components/BackgroundBar.tsx` — rewrite
`src/background/index.ts` — add `cancel()` method

## 11. Context Compaction System

### Concept

Manage context window growth during long sessions by pruning old tool results and preserving domain-critical state through compaction summaries.

### CompactionConfig

```ts
interface CompactionConfig {
  enabled: boolean;              // default: true
  autoThreshold: number;         // default: 90 (% — trigger auto-compact)
  warningThreshold: number;      // default: 70 (% — show yellow)
  toolResultPruning: {
    enabled: boolean;            // default: true
    keepRecentResults: number;   // default: 3
    minResultSizeBytes: number;  // default: 500
    neverPruneTools: string[];   // default: []
  };
}
```

### Tool Result Pruning

Continuous background optimization in `transformContext`:
- Walk messages backwards, keep last N tool results intact
- Prune older results > minResultSizeBytes with placeholder: `[Pruned: toolName — X bytes]`
- Never prune tools in `neverPruneTools`
- Only prune results with subsequent assistant message (not pending)

### Compaction Flow

1. After each agent turn, check context usage
2. Guard conditions (all must be true):
   - `percent >= autoThreshold`
   - `!state.isCompacting` (reentrancy guard)
   - No pending user messages in queue
   - Session phase is `ready` (not mid-stream)
3. If guards pass:
   - Dispatch `COMPACTION_START`
   - **try:**
     - Load instructions from `workspace/compaction/COMPACT.md` (fallback: hardcoded KLayout-domain prompt)
     - Call `session.compact(instructions)`
     - Extract structured state from summary XML tags → write to `workspace/compaction/` files
   - **catch:** Log error, dispatch `SYSTEM_MESSAGE` with error text
   - **finally:** Dispatch `COMPACTION_END` (always — prevents stuck `isCompacting`)
   - Refresh context usage
4. Manual compaction via `/compact [instructions]`

### COMPACT.md Template

Ship a default `workspace/compaction/COMPACT.md` with the onboard template:

```markdown
When summarizing this conversation, preserve:
- Active KLayout layout name and cell hierarchy
- Layer definitions used (layer/datatype pairs and their purpose)
- Geometry operations performed and their parameters
- Design constraints and rules discussed
- Current GDS file paths and save locations
- Plan mode progress and next steps

Structure your summary with these XML tags:
<layout-state>current layout and geometry state</layout-state>
<design-rules>active constraints and rules</design-rules>
<workspace-state>file paths, plan progress, next steps</workspace-state>
```

### State Extraction Tags

| XML Tag | Output File | Content |
|---------|-------------|---------|
| `<layout-state>` | `compaction/layout-state.md` | Active layout, cell hierarchy, layer config |
| `<design-rules>` | `compaction/design-rules.md` | DRC constraints, design rule parameters |
| `<workspace-state>` | `compaction/workspace-state.md` | File paths, GDS locations, plan progress |

### State Injection

`createStateLoaderTransform()` reads compaction state files and injects a `<compaction-state>` block into the last user message before each LLM call.

### transformContext Pipeline

```
messages → pruner → stateLoader → autoRecall → LLM
```

### Files

- `src/compaction/tool-result-pruner.ts`
- `src/compaction/state-extractor.ts`
- `src/compaction/state-loader.ts`

## 13. Agentic E2E Tests (5a-5g)

### Philosophy

Test the new features end-to-end via the RPC harness. Agentic tests use natural language prompts and verify outcomes, not tool sequences. Tests build on the existing `createRPCClient()` pattern with 420s call timeout and event capture.

### Test Suites

**Note on TUI vs RPC testing:** Markdown rendering, tab completion, and keyboard shortcuts are TUI-only features that cannot be verified via RPC (which emits raw model text, not rendered ANSI). These are tested via unit tests on the rendering pipeline. E2E tests via RPC validate command output content and context management behavior.

#### 5a: Markdown Pipeline (unit tests, not RPC)

| Test | Input | Verification |
|------|-------|-------------|
| renderMarkdown produces ANSI | `"# Hello\n\`\`\`python\nprint('hi')\n\`\`\`"` | Output contains ANSI escape codes, no raw `###` markers |
| Bullet replacement | `"- item one\n- item two"` | Output contains `•` not `-` |
| Code highlighting | `"```python\nx = 1\n```"` | Output contains ANSI color codes from cli-highlight |
| Empty input | `""` | Returns empty string |

#### 5b: Slash Command Completeness (RPC)

| Test | Steps | Verification |
|------|-------|-------------|
| /help lists all commands | Send `/help` | Response contains all 10 command names: model, mcp, config, context, memory, plan, tasks, compact, help, exit |
| /context shows workspace | Send `/context` | Response contains workspace file names and sizes |
| /compact is callable | Send `/compact` | Response indicates compaction (success or "nothing to compact"), no crash |
| /compact via shell | Run `qlaybot compact` | Shell command routing works (compact in COMMAND_NAMES) |

#### 5c: Context Compaction (RPC, tolerant assertions)

| Test | Steps | Verification |
|------|-------|-------------|
| Manual compact | 1. Run 4 bash commands generating >2KB output each | |
| | 2. Record `get_session_info` token count (before) | |
| | 3. Send `/compact` | Response indicates compaction completed |
| | 4. Record `get_session_info` token count (after) | After ≤ before (tokens don't increase after compact) |
| | 5. Send "What did we do?" | Agent responds coherently (status: completed) |

#### 5d: Tool Result Pruning (unit tests primary, RPC secondary)

**Unit tests (deterministic, in test-compaction.ts):**

| Test | Input | Verification |
|------|-------|-------------|
| Keeps last N results | 5 tool results, keepRecentResults=3 | First 2 pruned, last 3 intact |
| Respects minResultSizeBytes | 5 results, 2 below threshold | Only large results pruned |
| Respects neverPruneTools | Results from protected tool | Never pruned regardless of age/size |
| Placeholder format | Pruned result | Contains `[Pruned: toolName — N bytes]` |

**RPC (secondary, broad assertion):**

| Test | Steps | Verification |
|------|-------|-------------|
| Context doesn't explode | Run 6 bash commands with large output | `get_session_info` context tokens < 6x single-result size |

#### 5e: Compaction State Files (unit tests primary, RPC secondary)

**Unit tests (deterministic, in test-compaction.ts):**

| Test | Input | Verification |
|------|-------|-------------|
| extractTag parses XML | `"<layout-state>content</layout-state>"` | Returns `"content"` |
| extractStateFiles writes files | Summary with 3 XML tags | 3 files written to compaction dir |
| loadStateBlock reads files | Files in compaction dir | Returns `<compaction-state>` block |
| State loader injects block | Messages + state files | Last user message augmented with state block |

**RPC (secondary):**

| Test | Steps | Verification |
|------|-------|-------------|
| State survives compact | 1. Create layout + add geometry | |
| | 2. `/compact` | |
| | 3. Ask "What layers have geometry?" | Agent response mentions the layers (state re-injected) |

#### 5f: Workspace Integrity (RPC)

| Test | Steps | Verification |
|------|-------|-------------|
| /context shows files | Send `/context` | Response lists workspace file names with sizes |
| Context percentage | Send `/context` | Response includes context usage percentage |

#### 5g: Long Session Resilience (RPC)

| Test | Steps | Verification |
|------|-------|-------------|
| 10+ turn session | 1. Create layout, 2-9. Add geometry (one per turn), 10. Query state | |
| | Check `get_session_info` after turn 10 | Context usage < 80% (pruning active) |
| | Final query | Agent correctly describes layout contents |

Gated behind `QLAYBOT_NIGHTLY=1` — only runs during final integration test (too expensive for per-task runs). Must be written and must pass.

### Test Infrastructure

- Extend existing `createRPCClient()` with `events[]` capture (already done in v0.2)
- 360s per-test timeouts for agentic tests
- `get_session_info` returns `contextUsage` for assertions
- Tests 5a, 5d-unit, 5e-unit are fast (no LLM). Tests 5b, 5c, 5e-rpc, 5f are moderate. Test 5g is nightly-only.
- `/compact` must be added to `COMMAND_NAMES` in `src/commands/index.ts` for shell routing
