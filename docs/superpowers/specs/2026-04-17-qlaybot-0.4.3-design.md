**Date**: 2026-04-17

**References**:

## Summary

Version 0.4.3 adds one major feature and three minor features to qlaybot:

| Feature | Type | One-line summary |
|---------|------|------------------|
| **Plan Mode** | Major | Tool-based + slash-command plan mode with disk-persisted plan files and 4-option approval menu. Byte-for-byte port of qdevbot's implementation, adapted to the KLayout domain. |
| TUI image render | Minor | Decode `type: "image"` tool-result content to iTerm2 OSC 1337 inline escape, with terminal detection + save-to-file fallback. |
| Transcript truncate | Minor | Auto-truncate tool-result entries > 2000 chars in `~/.qlaybot/history/.../transcript.jsonl` and the per-tool JSON files, using 1000-head + 1000-tail with an `... (truncated N chars) ...` marker. |
| `--verbose` flag | Minor | Disables both TUI and disk truncation, prints the assembled system prompt on startup, emits per-turn timing + token stats, and writes a full-fidelity project-local transcript copy to `./qlaybot-transcripts/{sessionId}-{timestamp}.jsonl`. |

Integration approach: **refactor + unified truncation** (approach B from brainstorm). Replace qlaybot's existing skeletal `src/planning/index.ts` with a qdevbot-aligned `PlanManager`. One shared `src/truncation.ts` module powers both display and disk truncation; `--verbose` toggles it off in both places.

## 1. Plan Mode (Major)

### 1.1 Scope

qlaybot v0.4.2 already has a scaffolding for plan mode (`src/planning/index.ts`, `src/planning/sandbox.ts`, `src/commands/plan.ts`) — in-memory, slash-command-only, no plan-file persistence, no approval flow. 0.4.3 replaces this with a full qdevbot-parity implementation: dual entry paths (slash command + tools), disk persistence, sandboxed tool wrapping, and a TUI approval menu.

### 1.2 PlanManager (`src/planning/index.ts`, rewritten)

Port from qdevbot `src/planning/manager.ts` (217 lines) — verbatim port of:
- Private state fields: `_inPlanMode: boolean`, `_currentPlan: Plan | null`, `_plansDir: string`, `_listeners: PlanEventListener[]`.
- Public getters: `inPlanMode`, `currentPlan`, `plansDir`.
- Methods: `enterPlanMode(task: string, title?: string): Plan`, `exitPlanMode(approved?: boolean = true): Plan | null`, `reenterPlanMode(): Plan | null`, `updatePlanTasks(tasks: PlanTask[]): void`, `readPlanFile(): string | null`, `writePlanContent(content: string): void`, `subscribe(listener: PlanEventListener): () => void`.
- Private helpers: `_emit(event)`, `_deriveTitle(task)`, `_buildPlanFileContent(plan)`, `_writePlanFile(plan)`.
- Constructor: `new PlanManager(workspaceDir: string)` — sets `_plansDir = join(workspaceDir, "plans")`.

**Plan ID format**: `plan-${Date.now()}`.
**Plan file path**: `${plansDir}/${planId}.md`.
**Error handling**: `enterPlanMode` wraps `mkdirSync` + `writeFileSync` in try/catch; on failure (e.g., read-only workspace, disk full), the tool result returns `{status: "error", message: "Failed to create plan file: ${err.message}"}` without mutating `_inPlanMode` or `_currentPlan`.

**Plan file template** (emitted by `_buildPlanFileContent`, exact):

```
# {title}

## Task
{task}

## Plan

<!-- The agent will fill in the plan during plan mode -->

## Tasks

<!-- Checklist of implementation tasks -->
```

**Status marker** prepended on `exitPlanMode`:
- `approved` → `> Status: **approved**\n\n` at top of file
- `abandoned` → `> Status: **abandoned**\n\n`
- On `reenterPlanMode` → regex `content.replace(/^> Status:.*\n\n?/, "")` strips it.

**Events** (`PlanEventType`): `"plan_mode_entered"`, `"plan_mode_exited"`, `"plan_created"`, `"plan_updated"` — each carries `{type, planId?, timestamp}`.

### 1.4 Sandbox (`src/planning/sandbox.ts`, rewritten)

Port from qdevbot `src/planning/sandbox.ts` (135 lines) — three exported wrappers plus one helper predicate:

- `wrapWriteForPlanMode(tool, planManager, cwd)` — checks `params.path || params.file_path`, calls `isInsidePlansDir`, blocks if outside.
- `wrapEditForPlanMode(tool, planManager, cwd)` — identical predicate, different error phrasing (`"Cannot edit..."`).
- `wrapBashForPlanMode(tool, planManager)` — unconditional block when `inPlanMode`. Rationale comment: *"Bash is fully blocked because reliably distinguishing read-only commands from destructive ones is not feasible (pipes, subshells, aliases, etc.)"*.
- `isInsidePlansDir(filePath, plansDir, cwd)` — private helper:
  ```typescript
  const resolved = normalize(resolve(cwd, filePath));
  const normalizedPlansDir = normalize(plansDir);
  return resolved.startsWith(normalizedPlansDir + "/") || resolved === normalizedPlansDir;
  ```
- `blocked(reason)` — returns `AgentToolResult` with `content[0].text = JSON.stringify({error: "plan_mode_restricted", message: reason, hint: "You are in plan mode. Only the plan file can be modified. Use exit_plan_mode to leave plan mode first."})`.

Wrappers compose after any background-execution wrapping. Order preserved from qdevbot `tools/index.ts:45-77`.

### 1.5 KLayout MCP gate (`src/tools/annotations.ts` + `src/mcp/manager.ts`)

qdevbot wraps its single `instrmcp` proxy tool with `planManager` (see `src/tools/instrmcp.ts:158-169`). qlaybot routes KLayout tools through `MCPManager` + `klayout-client.ts`, and every KLayout tool is separately declared. Strategy:

1. **Extend `src/tools/annotations.ts`** so every KLayout MCP tool carries `readOnlyHint`, `destructiveHint`, `openWorldHint` booleans (MCP-standard annotation shape).
   - Read-only (allowed in plan mode): `get_layout_info`, `screenshot`, `route_inspect`, `validate_pixel_size`.
   - Destructive (blocked): `create_layout`, `save_layout`, `execute_script`, `auto_route`, `close_layout_view`, `evaluate_design`.
   - All klayout skill tools (geometry add_*, display toggle_*, image add_*/remove_*, nanodevice_*) → destructive.
2. **Add `isReadOnlyTool(annotations)` helper** in `src/planning/sandbox.ts` — deny-by-default precedence (qdevbot `src/tools/instrmcp.ts:13-20`):
   - `!annotations` → `false` (unknown = deny).
   - `destructiveHint === true` → `false`.
   - `openWorldHint === true` → `false`.
   - Otherwise `annotations.readOnlyHint === true`.
3. **Add `wrapMCPToolForPlanMode(tool, planManager, getAnnotations)`** — applied in `src/tools/index.ts` to every MCP-backed tool. When `inPlanMode`, call `getAnnotations(toolName)`, feed to `isReadOnlyTool`; on deny, return `planModeBlockedTool(name, annotations)` JSON with:
   ```typescript
   {
     error: "plan_mode_restricted",
     tool: name,
     reasons: string[],  // ["destructiveHint: true"] / ["readOnlyHint not set"] / ["no annotations (unknown safety)"]
     message: `Tool "${name}" is blocked during plan mode. Only read-only tools (readOnlyHint: true) are allowed. Reasons: ${reasons.join(", ")}.`,
     hint: `Use exit_plan_mode to leave plan mode.`,
   }
   ```

   - Expected outcomes and decision points

## 2. TUI Image Render (Minor)

### 2.1 Module (`src/tui/image-render.ts`, new)

```typescript
export type ImageRenderMode = "iterm2" | "fallback";

export function detectImageRenderMode(): ImageRenderMode {
  const term = process.env.TERM_PROGRAM || "";
  if (term === "iTerm.app" || term === "WezTerm" || term === "vscode") return "iterm2";
  return "fallback";
}

export function renderInlineImage(base64: string, opts?: {
  width?: string;  // default "auto"
  height?: string; // default "auto"
}): string {
  // iTerm2 OSC 1337 escape
  const w = opts?.width ?? "auto";
  const h = opts?.height ?? "auto";
  return `\x1b]1337;File=inline=1;width=${w};height=${h};preserveAspectRatio=1:${base64}\x07`;
}

export function renderFallback(base64: string, outDir: string): string {
  // Decode to /tmp, return "[image saved: <path>]"
}
```

### 2.2 Size cap

Hard cap: decoded size > 2 MB → always use fallback (even in iTerm2, to avoid freezing the terminal). 2 MB chosen because iTerm2 reliably handles it; larger images flicker or stall on some hosts.

### 2.3 Integration (`src/tui/components/ToolPanel.tsx`)

Tool results reach `ToolPanel` via the reducer's `ToolExecution` object. The tool-result content block array may contain `{type: "image", source: {type: "base64", media_type, data}}` per Anthropic content-block shape. When rendering the expanded result:

```typescript
for (const block of result.content ?? []) {
  if (block.type === "image") {
    const mode = detectImageRenderMode();
    if (mode === "iterm2" && base64DecodedSize(block.source.data) <= 2_000_000) {
      push(<Text>{renderInlineImage(block.source.data)}</Text>);
    } else {
      push(<Text>{renderFallback(block.source.data, tmpdir())}</Text>);
    }
  } else if (block.type === "text") {
    push(<Text>{block.text}</Text>);
  }
}
```

- No image resizing / thumbnailing.
- No GIF / animation support.
- Compact (unexpanded) tool view still shows a single-line summary (`"[image 512x512]"`) without rendering.

## 3. Transcript Truncate (Minor)

### 3.1 Module (`src/truncation.ts`, new, shared)

```typescript
export interface TruncationOptions {
  threshold: number;  // max chars before truncation applies
  headChars: number;  // chars to keep from the start
  tailChars: number;  // chars to keep from the end
}

export const DEFAULT_TRANSCRIPT_TRUNCATION: TruncationOptions = {
  threshold: 2000,
  headChars: 1000,
  tailChars: 1000,
};

export function truncate(s: string, opts: TruncationOptions): string {
  if (s.length <= opts.threshold) return s;
  const head = s.slice(0, opts.headChars);
  const tail = s.slice(s.length - opts.tailChars);
  const hidden = s.length - opts.headChars - opts.tailChars;
  return `${head}\n... (truncated ${hidden} chars) ...\n${tail}`;
}
```

### 3.2 Integration (`src/history.ts`)

`InteractionHistory.recordToolCall(entry)` currently writes two places:
1. A line to `transcript.jsonl`.
2. A full JSON file `tool_calls/NNN_{toolName}.json`.

Change:
- Before serializing the tool-result `content` field, run it through `truncate(content, DEFAULT_TRANSCRIPT_TRUNCATION)` **only for the `type: "tool_result"` entry**. Tool args are untruncated (they are bounded by model output).
- Apply to BOTH the transcript.jsonl line AND the per-tool JSON file (single source of truth — the full result is NOT preserved anywhere on disk unless `--verbose` is on).
- Non-tool-result entry types (`user_prompt`, `agent_response`, `agent_thinking`, `error`) are never truncated.

### 3.3 Verbose override

`--verbose` → pass `{threshold: Infinity}` (or skip the `truncate` call). Handled by a config lookup, not a separate code path.

### 4.3 Effects

1. **Disable TUI truncation** in `ToolPanel.tsx` — skip the 8-head/8-tail `formatResult` branch, render full result.
2. **Disable transcript truncation** in `history.ts` — see §3.3.
3. **Print system prompt on startup** — in `App.tsx` post-init effect, dispatch a SYSTEM_MESSAGE with the assembled system prompt. Guard: only if `verbose === true`.
4. **Per-turn timing + token usage** — in the event subscription bridge (`src/events.ts`), on `agent_end`, compute elapsed time since last `agent_start`, read token counts from the event payload, dispatch:
   ```
   SYSTEM_MESSAGE: [turn {n}: {elapsedMs}ms, in={inputTokens}, out={outputTokens}, thinking={thinkingTokens}]
   ```
5. **Project transcript copy** — new `src/verbose-transcript.ts`. On session start, open `./qlaybot-transcripts/{sessionId}-{YYYYMMDD-HHMMSS}.jsonl` in append mode (`fs.createWriteStream` with `flags: "a"`). One file per session, written line-by-line as events arrive — survives mid-session crashes as valid JSONL up to the last fsync. Mirrors every event written to `~/.qlaybot/history/.../transcript.jsonl` but with NO truncation applied. Close on session end. Cleanup: no auto-delete (user manages). Parent dir `./qlaybot-transcripts/` created on first write; if unwritable, log an error once to stderr and silently skip subsequent writes (don't break the session for an optional feature).

### 4.4 No config panel entry

Not exposed in the ConfigPanel.tsx for 0.4.3 — `--verbose` is a CLI-only debugging flag. Keeps the ConfigPanel surface stable.

## 8. Migration Notes

- Users with existing `~/.qlaybot/history/` get new truncated tool-result entries on next session; old entries unchanged.
- Users who upgrade mid-session will NOT see plan-mode tools registered until restart (tool assembly runs at session creation).
- Workspace-local `./plans/` directory will be auto-created when plan mode is first entered; add to `.gitignore` suggestions in README (`plans/` entries can be committed if user wants plan history in git).
- The removed `/plan` `CommandHandler` returns `"unknown command"` for ~10 ms during the upgrade window until the App-level handler is live — mitigated by restarting the session.
