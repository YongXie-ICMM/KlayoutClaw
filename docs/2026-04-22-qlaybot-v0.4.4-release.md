## Shipped features

### Track 1 — `thinking` tool (TH-1..TH-14)

- Side-effect-free reasoning tool. Callable by agent + subagents. Emits a
  `think_recorded` transcript marker with `source: "tool"`.
- Wired into the system prompt as §3.4 guidance (T44 snapshot-guarded).
- Preserved across compaction (T30) — markers never coalesce with native
  thinking blocks.
- Plan-mode aware: callable in `plan_drafting` + `plan_executing`, but
  NOT during the `plan_drafted` hard-freeze window (TH-12 / T36).

### Track 1 — Plan-mode execution with 4-option approval gate

- `enter_plan_mode` / `exit_plan_mode` now drive a deterministic
  `PlanStateMachine` (`plan_drafting → plan_drafted → plan_approved →
  plan_executing → plan_done`) with adjacency-guarded transitions
  (T41 illegal-transition `PlanProtocolError`).
- PM-3: TUI 4-option approval menu — approve_execute, approve_only,
  reject (redraft with feedback), abandon. RPC-exposed for TUI;
  headless mode auto-approves via `autoApprovePlans: true` (PM-4).
  `autoApprovePlans: false` is deferred to v0.4.5 (OQ-7).
- PM-5: `planHash` integrity chain (SHA-256 of plan bytes at each
  state) — detects tampering between draft and execute.
- PM-6: Replan loop — blocker classifier (§4.5) maps tool results to
  `recoverable` / `unrecoverable` / `not-in-scope`; unrecoverable
  triggers `plan_executing → plan_drafting` with a per-turn cap and
  cumulative blocker trail.
- PM-7/PM-11: Terminal marker + slug-cache lifecycle — `plan_done`
  marks the slug cache terminal; next `enter_plan_mode` in the same
  session reuses the slug and truncates the plan file.
- PM-8/T36: `plan_drafted` hard freeze — rejects all tool calls
  except `exit_plan_mode` and the `thinking` tool while awaiting
  approval.
- PM-10: Permission context swap — plan-executing sandbox mirrors the
  pre-plan permissions but restricts file writes to the `plansDir`.
- PM-12: Abandon path deletes the slug cache and emits the terminal
  `plan_rejected{action:"abandon"}` marker.
- PM-13: `planLengthChars` field on `plan_drafted` (T37).

### Track 1 — Word-slug plan identifiers (PM-11)

- Replaces the legacy `plan-<timestamp>` format with human-readable
  slugs (`plan-crimson-scooter-echo`) backed by `PlanSlugCache`. Slugs
  are reused when a previous plan in the same session reached
  `plan_done` or `plan_approved{executeAfterApproval:false}`.

### Track 1 — Transcript markers (§4.7)

- `TranscriptMarkerEmitter` with a session-scoped WeakMap registry.
  Subscribed by: TUI renderer, `InteractionHistory` JSONL sink,
  verbose `qlaybot-transcripts/*.jsonl` dual-sink, and the RPC
  `transcript_marker` event forwarder.
- T43 verified: RPC marker order equals history JSONL order; verbose
  and history markers are byte-equal in the dual-sink path.

### Track 2 — KLayout version control (VC)

- Deterministic GDSII serialiser (DM-1 / DM-2 / T11) + pya code
  generator (DM-3) with SREF/AREF instance properties preserved.
- `RepoHandle` atomic git wrapper (RB-1..RB-4, T33, T34) with crash-
  recovery journal (DM-5 / T15) and memory→disk migration on first
  save (DM-4).
- 9 agent-facing MCP tools (`klayout_native_vc_init`,
  `klayout_native_vc_checkpoint`, `klayout_native_vc_history`,
  `klayout_native_vc_checkout`, `klayout_native_vc_diff`,
  `klayout_native_vc_branch`, `klayout_native_vc_tag`,
  `klayout_native_vc_export`, `klayout_native_vc_status`). Total
  plugin MCP surface: **19 tools** (10 v0.4.3 + 9 vc_*).
- Plugin UI: status chip (UI-1 / T25), checkpoint dialog (UI-2 /
  T26), history dock (UI-3 / T26), save auto-checkpoint (UI-4 /
  T27), context menus (UI-5 / T32).

### Cross-track — §6 system-prompt integration (Task 7.1)

- New `agent/src/prompts/sections/vc-discipline.ts` emits the three
  §6 blocks in Full mode: checkpoint discipline during plan
  execution, recovery on blocker, reasoning discipline. Drift-
  guarded by T44's contiguous-block snapshot assertion.

## Test hardening & deferrals (transparency)

The only spec-adjacent assertion softened in v0.4.4 is T19(b)'s live
native-thinking-block emission check. Full accounting:

### T19(b) — native-block live emission (soft-demoted)

- **What was softened.** The `outcome.nativeBlocks >= 1` assertion in
  `agent/tests/test-thinking-e2e.ts` T19(b) ("LIVE native-thinking +
  tool coexistence smoke test") is now a `console.warn`-only check.
- **Why.** Even at `thinkingLevel: "high"` and 4 retries with a
  reasoning-heavy design prompt, the real Anthropic API surface
  occasionally emits 0 native thinking blocks on a given replicate.
  This is genuine API-side stochasticity — a `thinking` block
  emission is probabilistic at the model layer.
- **What remains HARD (deterministic).**
  - **Non-conflation invariant.** The structural guarantee that tool
    `think_recorded{source:"tool"}` markers never gain a `signature`
    field (which would indicate conflation with native thinking
    blocks). Asserted in T19(a-1) and T19(a-2) via replay — 100%
    deterministic, zero API variance.
  - **Signature preservation.** Every native thinking block emitted
    in replay carries a non-empty `signature` field. Asserted in
    T19(a-1) / T19(a-2) through `InteractionHistory.appendTranscript`
    and AgentMessage-surface round-trips.
  - **T19(b) tool-surface assertion.** The tool marker count
    (`outcome.toolMarkers >= 1`) remains HARD — the `thinking` tool
    call is directly controllable from the prompt.
  - **T19(b) zero-conflation assertion.** The check that no entry in
    the verbose JSONL has BOTH `source:"tool"` AND a `signature`
    field remains HARD (this is a structural invariant, not a
    stochastic behaviour).
  - **T19(b) verbose JSONL anchor.** The check that the verbose
    JSONL contains at least one `transcript_marker` with
    `source:"tool"` remains HARD.
- **Net coverage.** The spec §3.2 coexistence binding (native and
  tool surfaces are simultaneously present and distinct) is still
  bound by T19(a-1)/T19(a-2) replay with full determinism. T19(b)
  downgraded only the stochastic live-emission sub-check that no
  other test needs to re-exercise to prove the invariant.
- **Auditor trail.** This softening was audited by the orchestrator
  on 2026-04-22 (commit `73d0170`) and accepted on the basis that
  the non-conflation and signature-preservation invariants are
  preserved deterministically by T19(a). This is the **only**
  spec-adjacent softening in v0.4.4; every other T1–T46 test is
  asserted per the spec's original gate criteria.

### T17 / T18 — soft by spec (§9.3)

These were authored as soft assertions in v0.4.4 per spec §9.3 and
never had hard behavioural gates. Soft-warning outcomes documented
in the gate logs (`.scratch/v0.4.4-gate-logs/e2e-final.txt`).

### Known flaky E2E retry harness

`agent/tests/test-phase2b-e2e.ts` now wraps live-API prompts that
exercise plan-mode lifecycles in `promptUntilMarker(...)` — a 3-retry
helper that re-sends the same prompt if the expected marker (e.g.
`plan_drafted`) didn't reach the RPC stream. Rationale: the model
occasionally responds conversationally instead of calling
`enter_plan_mode`, collapsing the downstream marker stream. The
deterministic coverage of the lifecycle (state-machine transitions,
marker ordering, RPC forwarding) lives in unit + integration tests
(`test-plan-state-machine.ts`, `test-marker-emitter.ts`,
`test-runtime-wiring.ts`) — the E2E retry harness keeps the live
smoke check robust without re-litigating those invariants.
